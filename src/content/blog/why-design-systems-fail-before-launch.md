Every design system I've worked on started the same way: a Figma library, a set of tokens, and a lot of optimism. Most of them also hit the same wall six months in: components drift out of sync with code, teams route around the system instead of through it, and "using the design system" quietly becomes optional.

## The library isn't the system

The component library is the easiest part to build and the least important part to get right. The actual system is the set of decisions about *when* a new component gets added, *who* owns that decision, and *what happens* when a team needs something the system doesn't have yet. Skip that part, and the library becomes one more set of files to keep in sync by hand.

## Adoption is a incentive problem, not an awareness problem

Teams don't ignore design systems because they don't know they exist. They ignore them when using the system is slower than not using it. If a component is missing a variant, or the tokens don't quite match what design handed off, the path of least resistance is always a one-off. Every one-off is a small, rational decision that adds up to an unmaintained system.

## What actually works

The systems that stuck were the ones with a real feedback loop: a clear way to request new components, a fast turnaround on that request, and someone accountable for saying yes or no. Not a wiki page nobody reads. A process people actually go through, because going through it is faster than not.
